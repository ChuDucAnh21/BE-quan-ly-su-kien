## UC31 – Đăng ký tham gia sự kiện

| Trường                     | Nội dung                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tên Use Case**           | Đăng ký tham gia sự kiện (Mua vé)                                                                                                                                                                                                                                                                                                                                                                 |
| **Tác nhân**               | User, Organizer, Admin                                                                                                                                                                                                                                                                                                                                                                            |
| **Mục đích**               | Cho phép người dùng đăng ký tham gia sự kiện. Hệ thống tự phân luồng: vé miễn phí cấp ngay, vé trả phí tạo link thanh toán PayOS                                                                                                                                                                                                                                                                  |
| **Mức độ ưu tiên**         | Cao                                                                                                                                                                                                                                                                                                                                                                                               |
| **Điều kiện kích hoạt**    | Người dùng nhấn "Đăng ký" hoặc "Mua vé" trên trang chi tiết sự kiện                                                                                                                                                                                                                                                                                                                               |
| **Điều kiện tiên quyết**   | Đã đăng nhập. Sự kiện ở trạng thái PUBLISHED. Chưa hết chỗ. Sự kiện chưa bắt đầu. Người dùng chưa đăng ký sự kiện này                                                                                                                                                                                                                                                                             |
| **Điều kiện thất bại**     | Đăng ký không thành công. Hệ thống hiển thị lỗi cụ thể                                                                                                                                                                                                                                                                                                                                            |
| **Điều kiện thành công**   | Registration + Payment được tạo. Nếu miễn phí → Ticket được sinh ngay. Nếu có phí → checkoutUrl được trả về                                                                                                                                                                                                                                                                                       |
| **Luồng sự kiện chính**    | 1. Người dùng nhấn "Đăng ký/Mua vé". 2. Frontend gửi POST /registrations với {eventId}. 3. Hệ thống kiểm tra sự kiện PUBLISHED. 4. Hệ thống kiểm tra chưa qua startTime. 5. Hệ thống kiểm tra soldTickets < capacity. 6. Hệ thống kiểm tra User chưa đăng ký. 7. Hệ thống giữ chỗ: soldTickets += 1. 8. Hệ thống sinh mã đăng ký (UUID 8 ký tự viết hoa). 9. Hệ thống phân nhánh theo ticketPrice |
| **Luồng sự kiện thay thế** | 9a. ticketPrice = 0 (Miễn phí): Tạo Registration (CONFIRMED) + Payment ảo (provider=SYSTEM, amount=0, status=SUCCESS) + Sinh Ticket (ACTIVE) với qrCode = UUID 36 ký tự. 9b. ticketPrice > 0 (Trả phí): Tạo Registration (PENDING_PAYMENT) + Gọi PayOS SDK tạo link checkout + Lưu Payment (PENDING, checkoutUrl) + Trả checkoutUrl cho Frontend để redirect                                      |
| **Luồng sự kiện ngoại lệ** | 3a. Sự kiện chưa công bố hoặc đã bắt đầu → EVENT_NOT_STARTED (400). 5a. Hết chỗ → TICKET_SOLD_OUT (400). 6a. Đã đăng ký → ALREADY_REGISTERED (400). 9b1. Organizer chưa cấu hình PayOS → PAYMENT_CONFIG_NOT_FOUND (404)                                                                                                                                                                           |

## UC32 – Hủy đăng ký tham gia sự kiện (Vé Free hoặc Chưa thanh toán)

| Trường                     | Nội dung                                                                                                                                                                                                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Tên Use Case**           | Hủy đăng ký tham gia sự kiện                                                                                                                                                                                                                                                                                             |
| **Tác nhân**               | User, Organizer, Admin                                                                                                                                                                                                                                                                                                   |
| **Mục đích**               | Cho phép người dùng hủy vé miễn phí hoặc vé trả phí nhưng chưa thanh toán để nhường chỗ cho người khác                                                                                                                                                                                                                                                         |
| **Mức độ ưu tiên**         | Trung bình                                                                                                                                                                                                                                                                                                               |
| **Điều kiện kích hoạt**    | User nhấn "Hủy vé" trên trang vé đã đăng ký                                                                                                                                                                                                                                                                              |
| **Điều kiện tiên quyết**   | Đã đăng nhập. Vé thuộc sự kiện miễn phí (ticketPrice = 0) HOẶC vé có phí nhưng trạng thái đang là PENDING_PAYMENT. Sự kiện chưa diễn ra.                                                                                                                                                                                                                                                                |
| **Điều kiện thất bại**     | Vé không bị hủy. Hệ thống hiển thị lỗi                                                                                                                                                                                                                                                                                   |
| **Điều kiện thành công**   | Registration → CANCELLED. Ticket → INVALID (nếu đã sinh vé free). Payment → CANCELLED (nếu có). soldTickets -= 1 (nhả chỗ)                                                                                                                                                                                                                                                   |
| **Luồng sự kiện chính**    | 1. User nhấn "Hủy vé". 2. Hệ thống xác nhận. 3. User xác nhận hủy. 4. Frontend gửi POST /registrations/{id}/cancel. 5. Hệ thống kiểm tra quyền. 6. Hệ thống kiểm tra vé là Free hoặc Chưa thanh toán. 7. Hệ thống chuyển Registration → CANCELLED, Payment (nếu có) → CANCELLED, Ticket (nếu có) → INVALID. 8. Hệ thống nhả chỗ: soldTickets -= 1. 9. Hệ thống trả về thành công |
| **Luồng sự kiện thay thế** | 3a. User nhấn "Không" → Không hủy                                                                                                                                                                                                                                                                                        |
| **Luồng sự kiện ngoại lệ** | 5a. Vé trả phí đã thanh toán (CONFIRMED) → CANNOT_CANCEL_PAID_TICKET (400). 5b. Đã qua thời gian bắt đầu sự kiện → EVENT_NOT_STARTED (400)                                                                                                                                                                                                                                                                         |

## UC33 – Xử lý Webhook PayOS

| Trường                     | Nội dung                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tên Use Case**           | Nhận và xử lý Webhook thanh toán từ PayOS                                                                                                                                                                                                                                                                                                                                 |
| **Tác nhân**               | Hệ thống PayOS (External)                                                                                                                                                                                                                                                                                                                                                 |
| **Mục đích**               | Tự động xử lý kết quả thanh toán: cấp vé nếu thành công, hủy đơn nếu thất bại                                                                                                                                                                                                                                                                                             |
| **Mức độ ưu tiên**         | Cao                                                                                                                                                                                                                                                                                                                                                                       |
| **Điều kiện kích hoạt**    | PayOS gửi HTTP POST đến /payments/webhook sau khi khách hàng hoàn tất hoặc hủy thanh toán                                                                                                                                                                                                                                                                                 |
| **Điều kiện tiên quyết**   | Đơn hàng PENDING tồn tại trong CSDL. Organizer đã cấu hình PayOS hợp lệ                                                                                                                                                                                                                                                                                                   |
| **Điều kiện thất bại**     | Webhook bị từ chối do chữ ký không hợp lệ                                                                                                                                                                                                                                                                                                                                 |
| **Điều kiện thành công**   | Payment + Registration được cập nhật. Nếu thành công → Ticket (ACTIVE) được sinh                                                                                                                                                                                                                                                                                          |
| **Luồng sự kiện chính**    | 1. PayOS gửi POST /payments/webhook với JSON + HMAC signature. 2. Hệ thống lấy checksumKey từ PaymentConfig của Organizer. 3. Hệ thống xác thực chữ ký HMAC-SHA256. 4. Hệ thống truy vấn Payment bằng orderCode (PESSIMISTIC_WRITE Lock). 5. Hệ thống kiểm tra Idempotency: nếu status ≠ PENDING → bỏ qua, trả thành công. 6. Hệ thống phân nhánh theo kết quả thanh toán |
| **Luồng sự kiện thay thế** | 6a. Thanh toán thành công: Payment → SUCCESS, Registration → CONFIRMED, Sinh Ticket (ACTIVE) với UUID qrCode. 6b. Thanh toán thất bại/hủy: Payment → FAILED, Registration → CANCELLED, soldTickets -= 1 (nhả chỗ)                                                                                                                                                         |
| **Luồng sự kiện ngoại lệ** | 3a. Chữ ký HMAC không hợp lệ (giả mạo) → Hệ thống từ chối, trả lỗi. 4a. orderCode không tồn tại → Bỏ qua. 5a. Đơn đã xử lý (SUCCESS/FAILED/CANCELLED) → Bỏ qua (Idempotency)                                                                                                                                                                                              |

| Trường                     | Nội dung                                                                                                                                                                                                                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tên Use Case**           | Chủ động kiểm tra trạng thái đơn hàng trên PayOS                                                                                                                                                                                                                                          |

| **Mục đích**               | Cho phép Frontend đồng bộ trạng thái đơn hàng khi Webhook bị mất (do mạng lỗi hoặc Ngrok sập)                                                                                                                                                                                             |
| **Mức độ ưu tiên**         | Cao                                                                                                                                                                                                                                                                                       |
| **Điều kiện kích hoạt**    | User nhấn "Kiểm tra thanh toán" hoặc Frontend tự polling                                                                                                                                                                                                                                  |
| **Điều kiện tiên quyết**   | Đơn hàng tồn tại trong CSDL                                                                                                                                                                                                                                                               |
| **Điều kiện thất bại**     | Không kết nối được PayOS                                                                                                                                                                                                                                                                  |
| **Điều kiện thành công**   | Trạng thái đơn hàng được đồng bộ chính xác với PayOS                                                                                                                                                                                                                                      |
| **Luồng sự kiện chính**    | 1. Frontend gọi GET /payments/sync/{orderCode}. 2. Hệ thống kiểm tra Payment tồn tại. 3. Hệ thống kiểm tra nếu đã xử lý (SUCCESS/FAILED/CANCELLED) → trả kết quả ngay. 4. Nếu PENDING: gọi PayOS SDK payOS.paymentRequests().get(orderCode). 5. Hệ thống phân nhánh theo trạng thái PayOS |
| **Luồng sự kiện thay thế** | 5a. PAID → Cập nhật SUCCESS, sinh Ticket, trả "PAID_AND_TICKET_CREATED". 5b. CANCELLED/EXPIRED → Cập nhật FAILED, nhả chỗ, trả trạng thái. 5c. Vẫn PENDING → Trả "PENDING"                                                                                                                |
| **Luồng sự kiện ngoại lệ** | 2a. orderCode không tồn tại → PAYMENT_NOT_FOUND (404). 4a. Không kết nối được PayOS → UNCATEGORIZED_EXCEPTION (500)                                                                                                                                                                       |

## UC40 – Tự động hủy đơn hàng quá hạn

| Trường                     | Nội dung                                                                                                                                                                                                                                                                                                                               |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tên Use Case**           | Scheduler tự động hủy đơn PENDING quá 30 phút                                                                                                                                                                                                                                                                                           |
| **Tác nhân**               | Scheduler (Internal - PaymentTimeoutScheduler)                                                                                                                                                                                                                                                                                         |
| **Mục đích**               | Tự động giải phóng chỗ (capacity) khi người dùng không thanh toán trong thời gian cho phép                                                                                                                                                                                                                                             |
| **Mức độ ưu tiên**         | Cao                                                                                                                                                                                                                                                                                                                                    |
| **Điều kiện kích hoạt**    | Scheduler kích hoạt tự động mỗi 5 phút (fixedRate = 300000ms)                                                                                                                                                                                                                                                                           |
| **Điều kiện tiên quyết**   | Hệ thống đang chạy. Có đơn hàng PENDING quá 30 phút                                                                                                                                                                                                                                                                                     |
| **Điều kiện thất bại**     | Hệ thống gặp lỗi truy vấn CSDL                                                                                                                                                                                                                                                                                                         |
| **Điều kiện thành công**   | Tất cả đơn hàng PENDING quá 30 phút được hủy. Chỗ (capacity) được nhả lại                                                                                                                                                                                                                                                               |
| **Luồng sự kiện chính**    | 1. Mỗi 5 phút, Scheduler tự kích hoạt. 2. Hệ thống truy vấn: Payment có status=PENDING AND createdAt < (now - 30 phút). 3. Nếu không có đơn nào → Kết thúc. 4. Với mỗi đơn hết hạn: Hủy Payment (CANCELLED), Hủy Registration (CANCELLED), Nhả chỗ soldTickets -= 1. 5. Hệ thống lưu tất cả thay đổi vào CSDL. 6. Ghi log số đơn đã dọn |
| **Luồng sự kiện thay thế** | 3a. Không có đơn hết hạn → Scheduler kết thúc sớm, không thao tác                                                                                                                                                                                                                                                                      |
| **Luồng sự kiện ngoại lệ** | 4a. soldTickets đã = 0 → Không trừ thêm (bảo vệ số âm)                                                                                                                                                                                                                                                                                 |
